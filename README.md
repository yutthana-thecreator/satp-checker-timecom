# SATP Checker — TIME.com Project

ระบบตรวจเอกสาร acceptance ของโปรเจกต์ TIME.com (AGRID 2.0 / DC2DC) สำหรับทีม Nokia Field Service

เว็บตรวจเอกสาร SATP + Attachment Report (TIME DWDM / Nokia 1830) — ทำงานในเบราว์เซอร์ทั้งหมด ไฟล์เอกสาร**ไม่ถูกส่งออกจากเครื่องผู้ใช้** Vercel ทำหน้าที่แจกหน้าเว็บอย่างเดียว

## ใช้งาน
1. เปิดหน้าเว็บ → ลากไฟล์ PDF / zip / โฟลเดอร์ไซต์มาวาง (ต่อไซต์ = SATP 1 + Attachment 1)
2. กด **ตรวจเอกสาร** → ได้ตารางสรุปรายไซต์ คลิกไซต์เพื่อดูประเด็น (ระดับ 1 ครบถ้วน / 2 สอดคล้อง / 3 ค่าทางเทคนิค พร้อมหน้า-section)
3. แท็บ **ตรวจรูป** → กด Accept / Reject ทีละรูป (Reject ต้องเลือกเหตุผล) ระบบช่วยแจ้งรูปซ้ำ/เบลอ
4. **ดาวน์โหลด Excel** → ชีท สรุป · ประเด็น · ตรวจรูป · ข้อมูลไซต์
5. ปุ่ม **เกณฑ์ตรวจ** แก้ค่าเกณฑ์ได้ (เก็บในเบราว์เซอร์เครื่องนั้น) ค่าว่าง = ไม่ตัดสิน

ประวัติการตรวจและผล Accept/Reject เก็บใน localStorage ของเบราว์เซอร์เครื่องนั้นเท่านั้น

```

src/engine/profiles.js โปรไฟล์อ้างอิง P1–P5 + เกณฑ์เริ่มต้น (จากตัวอย่าง 46 ไซต์)
src/data/sites.js     รายชื่อ 56 ไซต์โปรเจกต์ไทย (Masterfile col C–F) — hardcode
src/ui/images.js      งานรูป: ดึงรูปจากหน้า, hash หารูปซ้ำ, วัดความเบลอ

src/ui/cloud.js       Supabase: login (magic link), อ่าน/เขียนฐานความรู้ร่วม, รูปย่อใน Storage

supabase/schema.sql   ตาราง + RLS + bucket สำหรับฐานความรู้ร่วม
test/run-samples.mjs  รัน engine กับเอกสารตัวอย่างใน ../AGRID ../DC2DC (Node)
```

## อัปเดตข้อมูล
- **รายชื่อไซต์**: แก้ `src/data/sites.js` (ชีท `Schedule Plan I&C Thai` col C–F ของ Masterfile) แล้ว deploy ใหม่
- **เกณฑ์เริ่มต้น / โปรไฟล์**: `src/engine/profiles.js`
- **กฎ**: `src/engine/rules.js` (รหัส R01–R26 ตรงกับชีท "2_กฎตรวจ" ใน AI_Acceptance_Check_Reference.xlsx)

## ระบบเรียนรู้จากการตัดสินใจของ ROM (ฐานความรู้)
สิ่งที่ระบบตัดสินเองไม่ได้จะมีปุ่มให้ ROM ตัดสิน และผลถูกเก็บเป็นข้อมูลอ้างอิงสำหรับครั้งต่อไป:
- **ประเด็น** (เตือน/ข้อมูล หรือที่ระบุ "คนตรวจ/ROM/CPM") → ปุ่ม *ยอมรับ* / *ยืนยันปัญหา* + เหตุผล — ประเด็นชนิดเดียวกัน (กฎ+section+ประเภท+โปรไฟล์+ข้อความที่ตัดตัวเลข/รหัสไซต์ออก) ในไซต์ต่อไปจะถูกติดป้าย "ยอมรับแล้ว" อัตโนมัติและไม่นับเป็นเตือน
- **ไซต์ที่ไม่ตรงโปรไฟล์ใด** → ปุ่ม *ROM ยืนยัน: ใช้ไซต์นี้เป็นอ้างอิง* → บันทึกเป็นโปรไฟล์ใหม่ L1, L2, … (config + ค่าที่วัด) ไซต์ต่อไปที่ config เดียวกันจะจับคู่โปรไฟล์นี้และนับตัวอย่างเพิ่ม
- **รูป** → Accept = เก็บรูปย่อเป็นรูปอ้างอิงของ (โปรไฟล์ × section) แสดงเทียบข้างรูปใหม่ (สูงสุด 3 รูป/หัวข้อ) · Reject = จำ hash + เหตุผล ถ้ารูปเดิมโผล่อีกจะเตือน
- ฐานความรู้อยู่ในเบราว์เซอร์เครื่องนั้น (localStorage + IndexedDB) — ปุ่ม *ส่งออก/นำเข้า JSON* เพื่อแชร์ในทีม ไฟล์นี้ไม่มีเนื้อหาเอกสาร มีแต่ลายเซ็นประเด็น, ค่าที่วัด, รูปย่อที่ Accept

## ฐานความรู้ร่วมของทีม (Supabase)
ฐานความรู้ซิงก์กับ Supabase project `satp-checker-timecom` โดยไม่ต้อง login (ตัดสินใจโดยผู้ใช้ 2026-09-29) — ใครที่รู้ URL เว็บก็อ่าน/เขียนได้ ถ้าต้องการจำกัดให้เปิด Password Protection ของ Vercel
ตั้งค่าครั้งแรก: รัน `supabase/schema.sql` แล้วตามด้วย `supabase/no-login.sql` ใน SQL Editor · ใส่ Project URL + publishable key ใน `src/config.js`
(ถ้าภายหลังต้องการบังคับ login: ลบ policy `kb_anon`/`thumbs_anon_*` แล้วเปิดใช้ magic link ตามโค้ดเดิมใน git history)

สิ่งที่ขึ้นคลาวด์: การตัดสินใจประเด็น, ผล Accept/Reject (hash), โปรไฟล์ที่เรียนรู้, รูปย่ออ้างอิง (~30 KB/รูป), สถิติจำนวนรูปต่อหัวข้อ — ไฟล์ PDF และรูปเต็มไม่ออกจากเครื่อง
ทุกการตัดสินใจใหม่ขึ้นคลาวด์ทันที เปิดหน้าเว็บ/กด "ซิงก์" จะดึงของทีมลงมา ปุ่ม "อัปโหลดฐานความรู้ในเครื่องขึ้นคลาวด์" ใช้ย้ายข้อมูลเดิมครั้งแรก ปุ่มล้างมีผลเฉพาะเครื่องนั้น

## รูปอ้างอิงจากไซต์ที่ลูกค้าเซ็นแล้ว
ไฟล์ที่มี Acceptance Date หรือ `_Signed` = ลูกค้ายืนยันว่ารูปชุดนั้นใช้ได้ → ระบบเก็บทุกรูปเป็นรูปอ้างอิงของ (โปรไฟล์ × หัวข้อ เช่น "1.8 (a) Rack Installation") อัตโนมัติตอนตรวจ พร้อมจำจำนวนรูปต่อหัวข้อ
ในแท็บตรวจรูปของไซต์ใหม่โปรไฟล์เดียวกัน: แต่ละหัวข้อแสดงรูปอ้างอิงเทียบข้างกัน, เตือนเมื่อจำนวนรูปต่างจากไซต์ที่เซ็นแล้ว, เตือนเมื่อรูปเหมือนรูปของไซต์ที่เซ็นแล้ว (นำรูปมาใช้ซ้ำ) ROM ถอดรูปอ้างอิงที่ไม่เหมาะออกได้ (ปุ่ม ×)

## OCR screenshot (แท็บ "OCR screenshot" ต่อไซต์)
ใช้ Tesseract.js ในเบราว์เซอร์ (โหลดโมเดลจาก CDN ครั้งแรก ~10 MB แล้ว cache) ใช้เวลา ~5–10 วินาที/รูป:
- O01 Inventory: การ์ดตามโปรไฟล์, จำนวน shelf, วันที่-เวลา PC
- O02 Power: ค่าแรงดันในรูป vs ตาราง 1.5 (ข้อมูลเท่านั้น — อ่านตัวเลขบนรูปได้จำกัด)
- O03 NE Setup: IP/ชื่อ NE ตรงหน้า 1, วันที่-เวลา
- O04 ป้าย NE ID: มีรหัสไซต์
- O05 Fiber scope: PASS/FAIL และชื่อรายงานครอบคลุม LINE IN/OUT ทุกไซต์ปลายทาง
- O06 Block Diagram: ชื่อ NE และไซต์ปลายทางตรงตาราง Span Loss
ผล OCR ทุกข้อเป็น "เตือน/ข้อมูล" ให้คนยืนยัน (OCR อ่านผิดได้) และเข้าไปในแท็บประเด็น + Excel

## ขอบเขตปัจจุบัน (v0.2.0)
- ตรวจข้อความระดับ 1–3 ตามกฎ 26 ข้อ · จับคู่โปรไฟล์ P1–P5 + โปรไฟล์ที่เรียนรู้ · ตรวจข้ามไซต์ในชุดเดียวกัน
- ตรวจรูป: ดึงรูปทุก section, หารูปซ้ำ, วัดความเบลอ, Accept/Reject โดยคน, รูปอ้างอิงเทียบข้างกัน, OCR
- ประเภทที่ไม่มีโปรไฟล์ (EILA, PSI-M, ไฟ AC, Raman, 6–8 ทิศ) → กฎทั่วไป + ป้าย "ROM ตรวจเอง" + ปุ่มบันทึกเป็นอ้างอิง
- ยังไม่มี: ตรวจช่องลายเซ็นจากรูป (ใช้วันที่ท้ายหน้าแทน), OCR ตาราง Inventory ตัวเล็ก (อ่านได้จำกัด)
